# Shiplog Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship Shiplog: a hosted GitHub App + web app that understands repo changes, writes build-in-public posts in the user's voice on a configurable schedule, lets the user review them in an inbox, learns from edits, and posts through the Buffer API. Live and submitted by **Nov 13, 9pm IST**.

**Architecture:** GitHub webhooks are stored as events. An analyser turns each event into a cached "change card" (what / why / how / impact / significance). A 15-min cron decides per Project when a digest or instant post is due. A composer (Claude + project brief + voice memory) writes drafts into an inbox. Approving calls Buffer `createPost`. Edits are diffed into voice rules. See `docs/plans/2026-11-08-shiplog-design.md`.

**Tech Stack:** Next.js (App Router) + TypeScript, yarn, Vercel (hosting + Cron), Neon Postgres + Drizzle, BoardUI (React 19 / Tailwind v4 / React Aria / TanStack Table), Octokit (GitHub App), Anthropic SDK (`claude-sonnet-5-5`), Vitest, Zod.

**Repo:** new repo at `~/Documents/github/shiplog` (separate from these notes). Commit often, locally only. **Never push** unless the user says so. **No co-author lines** in commits.

```ts
// src/lib/budget.ts
export const LIMITS = { "15m": 100, "24h": 250, "30d": 3000 } as const;
type Usage = Record<keyof typeof LIMITS, number>;

export function windowsFor(d: Date): string[] {
  const iso = d.toISOString();
  const q = Math.floor(d.getUTCMinutes() / 15) * 15;
  return [
    `15m:${iso.slice(0, 11)}${String(d.getUTCHours()).padStart(2, "0")}:${String(q).padStart(2, "0")}`,
    `24h:${iso.slice(0, 10)}`,
    `30d:${iso.slice(0, 7)}`,
  ];
}

export function shouldBackOff(u: Usage, ratio = 0.8): boolean {
  return (Object.keys(LIMITS) as (keyof typeof LIMITS)[]).some((k) => u[k] >= LIMITS[k] * ratio);
}
```
(The 30d window is approximated by the calendar month; that's good enough for the contest.)

# 300-word summary (draft)
> **Shiplog** turns the work you ship into build-in-public posts that sound like you.
>
> Developers ship every day and post about it rarely. Writing the update takes longer than the change did, and commit messages like "fix stuff" make poor posts. Shiplog closes that gap.
>
> Install the GitHub App on one or more repos and group them into a Project. Shiplog builds a brief of what the project is (pitch, audience, architecture, a glossary of your internal names), then reads every commit, merged PR and release. It turns each one into a change card: what changed, why, how, and the impact. When it can't tell *why*, it asks you one short question instead of guessing. Secrets are scrubbed, and code is never quoted unless you allow it.
>
> On your schedule (a daily or weekly digest, plus instant posts for releases), it writes one post per network in your voice. Your voice comes from posts you've already sent through Buffer, and it gets sharper as you edit: Shiplog compares its draft with your final version and learns rules like "never says 'excited to announce'".
>
> Drafts wait in an inbox where you edit, regenerate with a nudge, or approve. Approved posts go out through the Buffer API at your best slot, or as Buffer drafts. Projects that have earned it can run on autopilot behind a rule and voice gate.
>
> Built on the Buffer API with OAuth + PKCE, single-flight token refresh, idempotent posting and a shared-quota budget meter. A demo mode runs the whole loop without any account.
>
> Every build-in-public post about Shiplog during the contest was written by Shiplog.
